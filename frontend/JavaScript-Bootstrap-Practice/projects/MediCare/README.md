
# MediCare Hospital Website

A responsive hospital website built using HTML, Bootstrap, Bootstrap Icons, and custom CSS.

## Project Overview

MediCare is a healthcare landing page designed to present hospital services, introduce doctors, display hospital statistics, and provide an appointment booking interface.

The project focuses on responsive layouts, semantic HTML, Bootstrap components, and custom CSS styling.

## Features

- Responsive navigation bar with a collapsible mobile menu
- Healthcare hero section with call-to-action buttons
- Hospital services displayed using Bootstrap cards
- Doctor profiles with images and experience badges
- Emergency hotline section
- Hospital statistics dashboard
- Appointment booking form
- Contact information and social media links
- CSS hover effects and transitions

## Technologies Used

| Technology | Purpose |
|---|---|
| HTML5 | Structures the website and its content. |
| Bootstrap | Provides responsive layouts, components, and utility classes. |
| Bootstrap Icons | Displays healthcare, navigation, and social media icons. |
| CSS3 | Adds custom styling, hover effects, and transitions. |
| JavaScript | Bootstrap's JavaScript bundle supports the responsive navigation toggle. |

## HTML Elements and Their Usage

| Element | Use |
|---|---|
| `<header>` | Contains the website's introductory content and navigation. |
| `<nav>` | Groups navigation links. |
| `<main>` | Contains the primary page content. |
| `<section>` | Groups related content, such as services and doctors. |
| `<article>` | Represents individual service and doctor cards. |
| `<h1>`–`<h3>` | Establishes the page's heading hierarchy. |
| `<img>` | Displays hospital and doctor images. |
| `<a>` | Provides navigation and call-to-action links. |
| `<button>` | Provides interactive controls. |
| `<form>` | Groups appointment booking inputs. |
| `<input>` | Collects patient information and appointment dates. |
| `<select>` | Allows users to select a medical department. |
| `<label>` | Identifies form controls for users. |
| `<footer>` | Contains contact details, quick links, and copyright information. |

## Bootstrap Components and Utilities

| Component / Class | Use |
|---|---|
| `navbar` | Creates the main navigation bar. |
| `navbar-toggler` | Provides the mobile navigation toggle button. |
| `collapse` | Controls the visibility of collapsible navigation content. |
| `container` | Provides a responsive content wrapper. |
| `row` and `col-md-4` | Organize content into responsive grid columns. |
| `card` and `card-body` | Structure the service, doctor, and statistics cards. |
| `badge` | Displays doctor experience labels. |
| `alert` | Highlights the emergency hotline. |
| `form-control` | Styles text, email, and date inputs. |
| `form-select` | Styles the department selection field. |
| `btn` | Styles buttons and call-to-action links. |
| `d-flex` and `align-items-center` | Aligns content using Flexbox. |
| `g-4` and `g-lg-5` | Controls responsive spacing between grid items. |
| `rounded-4` and `shadow-sm` | Applies rounded corners and subtle shadows. |
| `text-primary` and `fw-bold` | Applies theme colors and font weight. |

## CSS Concepts Practiced

| Property / Selector | Use |
|---|---|
| `object-fit: cover` | Maintains image proportions while filling the image container. |
| `object-position` | Controls which part of an image remains visible. |
| `transition` | Creates smooth visual changes. |
| `transform: scale()` | Adds a subtle image hover effect. |
| `transform: translateY()` | Creates a card lift effect. |
| `box-shadow` | Adds depth to cards. |
| `linear-gradient()` | Creates the footer's gradient background. |
| `:hover` | Applies styles when a user points to an element. |

## Learning Objectives

- Understand Bootstrap's responsive grid system.
- Practice semantic HTML structure.
- Use Bootstrap cards, navigation, forms, and utilities.
- Apply custom CSS without unnecessarily overriding Bootstrap.
- Build a responsive and accessible healthcare landing page.
- Organize frontend project files professionally.

## Current Limitations

- The appointment form is a frontend interface only and does not store or submit appointment data to a backend.
- The service and doctor buttons do not yet perform their intended actions.
- The emergency call link and social media links require valid destinations.

## Project Status

Frontend practice project — completed for the current learning stage.

Future improvements may include JavaScript form validation, interactive appointment handling, and backend integration.
